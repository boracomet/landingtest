ACF-Go

Custom fields: field groups, field types, location rules, options pages, blocks and REST (Advanced Custom Fields PRO).

ACF-Go is Pursae's native (compiled-in) clone of Advanced Custom Fields PRO 6.x. This file is the inventory of what ACF PRO does, written from ACF's documentation (advancedcustomfields.com/resources), the wordpress.org plugin page and the AdvancedCustomFields/acf source, and what ACF-Go does with each item. Status: ✓ implemented, ◐ implemented in a reduced form (the note says how), ✗ left out (the note says why).

ACF-Go is a native plugin like Classic Editor, WPGo Cache and Golementor: it is listed on Plugins, starts off, adds nothing to the site while off (no menu, screens, meta boxes, REST field, template output, routes answer 404) and keeps every field group and saved value when deactivated.

4. Presentation and group settings

Style (standard/WP box, seamless), Position (high after title, normal, side), Label placement (top/left), Instruction placement (below labels/below fields, tooltip), Order No., Description, Hide on screen (permalink, the content editor, excerpt, discussion, comments, revisions, slug, author, format, page attributes, featured image, categories, tags, send trackbacks) — ✓ in the classic editor. In Gotenberg the boxes sit in the editor's meta box pane (normal and side) and are saved with the post through the meta box request, like ACF; acf_after_title falls back to normal and hide-on-screen applies to the classic editor only (ACF behaves the same).

5. Conditional logic

Show this field if (OR groups of AND rules) against other fields of the group: has any value, has no value, value is equal to, not equal to, matches pattern, contains, greater than, less than, selection is greater/less than. ✓ in the editor (live) and on save (hidden fields are disabled, so their stored values stay untouched, as in ACF).

6. Validation

Required, character limit, min/max number, email/URL format, min/max rows/selections/images, image dimensions/size, file types — ✓ ajax validation before submit (acf/validate_save_post equivalent) and server-side on REST writes. Custom acf/validate_value filters ✗ (no PHP hooks; Wasm plugins can use REST).

7. Options pages (PRO, UI-created since 6.2)

ACF › Options Pages: page title, menu slug, parent page (top level or under any menu), menu position, icon (dashicon), menu title, capability, redirect to first child, update button label, updated message, description, data storage (options or a custom post id post_id), autoload — ✓. Each options page is /wp-admin/admin?page=<slug> with the field groups whose location is that page.

8. Post Types and Taxonomies UI (6.1+)

ACF › Post Types / Taxonomies: labels (all generated from singular/plural, editable), public, hierarchical, supports, taxonomies, menu icon/position, show in REST, REST base, archive, rewrite slug, capability type, exclude from search, delete with user… — ✓ stored as acf-post-type / acf-taxonomy posts; on save the type/taxonomy is registered (content_types / taxonomies rows), gets its admin menu (All / Add New, its taxonomies), the core's list, add and edit screens (classic editor) and term screens, and every role receives the type's capabilities (capability type "post"). ◐ Gotenberg, REST routes (/wp/v2/<rest_base>) and front-end permalinks/archives of custom post types need core support for arbitrary types and are not built (see "Left out").

9. ACF Blocks (PRO)

block.json with an acf key (renderTemplate, mode), registered with register_block_type() — ◐ ACF-Go registers blocks from acf-blocks/<name>/block.json folders (in <data>/acf-blocks or the active theme package) with a Go html/template render template (render.html); the block appears in Gotenberg's inserter (category from block.json), its fields are edited in the block (Edit/Preview toggle, server-rendered preview), values live in the block's data attribute like ACF, and the front end renders the template with get_field reading the block's data. Field groups target blocks with the Block location rule.

10. REST API

acf object for field groups with "Show in REST API": ✓ /wp/v2/posts and /pages read and write (POST {"acf": {"field_name": value}} with sub fields by name, validated before the post is saved, unknown names rejected), /users and /categories / /tags read. ?acf_format=standard returns formatted values, the default (light) stored values with typed IDs/numbers/booleans. ◐ Writes to users/terms and the /comments, /media objects are not built.

11. Template functions

get_field, the_field, get_field_object, get_fields, get_field_objects, have_rows / get_sub_field / the_sub_field / get_row_layout / get_row_index / get_row — ✓ as template functions for every theme (bundled and theme packages; Go templates take the post explicitly and range over rows instead of the_row()), and acfGetField, acfGetFieldObject, acfGetFields, acfUpdateField (update_field), acfDeleteField (delete_field) for Go code. Wasm plugins: ✓ get_post (host API, posts:read) returns an acf object with the post's field values (stored format) while ACF-Go is active (PostData.ACF in the Go SDK).

Theme template usage:

{{get_field "subtitle" .Post}}                 value (formatted) of the post in the loop
{{the_field "subtitle" .Post}}                 the same, HTML-escaped for output
{{get_field "phone" "option"}}                 options page value; "user_3", "term_5", "comment_9" too
{{range have_rows "slides" .Post}}{{get_sub_field "title" .}} ({{.Index}}){{end}}
{{range have_rows "sections" .Post}}{{if eq .Layout "hero"}}…{{end}}{{end}}   flexible content
{{with get_field_object "price" .Post}}{{.label}}: {{.value}}{{end}}

12. Tools

ACF › Tools: Export field groups, post types, taxonomies and options pages (download a .json file or show the JSON), Import JSON (any of them; existing items with the same key are updated) — ✓. Generate PHP ✗ (no PHP; the JSON is what local JSON and acfgoRegisterLocalGroup take). Import from CPT UI ✗.

13. Settings / misc

The ACF menu needs manage_options; option acfgo_show_admin = "0" hides it (ACF's show_admin setting) ✓. Field group / field keys visible in the editor and list ✓. ACF › Updates (licence) ✗ — nothing to license.

How it is wired

Native plugin switch native_acfgo (Plugins screen, default off). Code: internal/server/acfgo*.go, templates web/admin/templates/pages/acfgo.html, assets web/admin/assets/acfgo/. No migration: field groups, post types, taxonomies and options pages are posts of the acf-* content types (created on activation). Values live in posts.meta, users.meta, terms.meta, comments.meta, media.meta and the options table. The core's edit screens are reached through one gin middleware (it queues the boxes, which acfgo-input.js moves into the form, and saves acf[...] before the core's handler runs) plus small hooks: menu (adminPage), admin-ajax, REST serializers and post writes, the template FuncMap, admin?page= options pages, label lookups for ACF post types/taxonomies, the Wasm get_post payload.

Left out (and why)

  • Widget, nav menu and nav menu item locations: no meta storage in Pursae for them.
  • Field value revisions: core revisions do not store meta.
  • Bidirectional relationships (6.2): updating the other post's field on save.
  • PHP APIs/hooks (acf/load_value, acf/format_value, acf/validate_value filters, acf_form() front-end forms): there is no PHP; Wasm plugins read values through get_post and write through REST.
  • Repeater pagination, select2 "stylised UI"/ajax selects, the wpLink modal, jQuery UI date pickers and the Google Maps JS picker: replaced by simpler native controls (settings are kept and exported unchanged).
  • Custom post types: Gotenberg editing, REST routes and front-end single/archive routing (the core only routes post and page). ACF taxonomies on posts/pages work everywhere the core's term screens and post terms do; their front-end archives are not routed either.
  • REST writes for users and terms; acf on /comments and /media responses.
