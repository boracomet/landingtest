Maintenance-Go

Maintenance and coming-soon mode (clone of the Maintenance plugin by WebFactory).

Maintenance-Go is a native (compiled-in) Pursae plugin that clones Maintenance by WebFactory (wordpress.org/plugins/maintenance, v4.32, 2026-07-13). It also includes the parts of Maintenance PRO that make sense for a single-site Go install. Like Classic Editor, WPGo Cache and Golementor, it is off on a fresh install, and while it is off nothing of it runs or shows anywhere.

Sources: the plugin's wordpress.org page, readme and changelog, and the v4.32 source (maintenance.php with class MTNC, and frontend/index.php); the PRO feature list on wpmaintenancemode.com. SeedProd Coming Soon was consulted only where Maintenance lacks a basic piece: a separate Coming Soon / 200 mode, and a countdown that auto-disables.

Legend: ✓ implemented · ≈ implemented differently (reason given) · ✗ left out (reason given).

1. How the original works (summary of the research)

  • Storage. All options live in one option, mtnc-options. The admin page is a top-level Maintenance menu (manage_options) with these tabs: Themes · Design · SEO · Access · Advanced · PRO.
  • The gate. It is a template_include filter. It never touches cron, ajax, WP-CLI or is_admin() requests, nor URLs containing /wp-login.php, /wp-admin/, /async-upload.php, /upgrade.php or /xmlrpc.php.
    • REST, feeds, robots.txt and sitemaps exit before template_include, so the free plugin never gates them. PRO has an "Enable WordPress Rest API" switch.
  • Who sees the site, checked in this order:
    1. Search engine crawlers (PRO excludese, a list of 24 user agents).
    2. Any logged-in user (show_logged_in, on by default; there is no role filter).
    3. An exact REMOTE_ADDR match in the IP whitelist (PRO).
    4. URL rules (whitelist / blacklist). The path is lowercased, slashit()-normalized, and must match exactly.
    5. The secret link home/?<secret>, which sets a 24-hour cookie (PRO).
    6. The direct-access password, also stored in a cookie (PRO).
  • Status code. 503 with Retry-After: 3600 when blockse is on. In 4.32 that toggle is not in the save whitelist, so the free plugin really serves 200. nocache_headers() is always sent.
  • ?maintenance-preview shows the page to anyone, even while the mode is off.
  • Admin bar. A "Maintenance" node with a status dot, an ON/OFF toggle, Preview and Settings.
  • Default page. Full-screen background image with an overlay, a centered headline, text and footer. A padlock button in the lower right slides in a login form. There is no wp_head().
  • PRO adds: 200+ themes and a drag-and-drop builder with these modules: countdown, form (e-mail collection), social icons, progress bar, map, video and custom HTML. It also adds SEO fields (meta description, favicon, og image, tracking code), IP whitelist, secret link, site password, no-cache headers, toolbar on/off, force SSL, REST toggle, customizing the core update page and white-label.

3. How it is built

  • Files:
    • internal/server/maintenance.go: settings, gate, bypass rules, headers
    • maintenance_page.go: themes, fonts and render
    • maintenance/page.html: the embedded public page
    • maintenance_admin.go: screen, actions, menu, toolbar, import/export
    • maintenance_subscribers.go
    • web/admin/templates/pages/maintenance.html
    • Tests: maintenance_test.go
  • Settings. All settings sit in one option, maintenance_settings, read over the defaults in code, so settings.Defaults is untouched. The plugin switch is native_maintenance.
  • Where the gate runs. Server.Handler calls maintenanceServe before the page cache. So:
    • a closed site never serves a cached page to a visitor;
    • the maintenance page is written by the gate with no-store headers and never enters the cache;
    • bypassing users go on to the normal cache and app as usual.
  • Cache purges. These all call purgeAll: saving any tab, the toolbar toggle, activating or deactivating the plugin, import, reset, and the countdown's auto-disable.
  • The gate runs before the router, so it resolves the login cookie itself (maintUser). Its security headers are the front end's, with Google Analytics added only while an ID is set.
  • Hooks into shared files, one or two lines each:
    • server.go (Handler)
    • plugins.go (row, activate/deactivate case, reserved slug, icon)
    • admin.go (menu, toolbar node)
    • site_head.go (front-end toolbar node)
    • wpgocache.go (admin?page=maintenance dispatch)
