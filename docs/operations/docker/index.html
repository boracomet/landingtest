Docs/ Running in production/Docker

Docker

The image, the compose file, volumes, environment and running behind another compose stack.

The image

docker/Dockerfile is a two-stage build: golang:1.27-alpine compiles a static binary, the final stage is alpine:3.22 with ca-certificates and tzdata, an unprivileged user wpgo (uid 10001) and the data directories /data/uploads, /data/plugins, /data/plugin-cache, /data/mail and /data/themes. The entrypoint is wpgo, the default command serve, the exposed port 8080. Example plugin packages from examples/plugins/dist are copied to /usr/share/wpgo/plugins if they exist.

docker build -f docker/Dockerfile -t wpgo:local .
docker run --rm -p 8080:8080 \
  -e DATABASE_URL='postgres://wpgo:wpgo@db:5432/wpgo?sslmode=disable' \
  -e WPGO_SITE_URL=https://blog.example.com \
  -e WPGO_UPLOADS_DIR=/data/uploads \
  -v wpgo-uploads:/data/uploads -v wpgo-plugins:/data/plugins -v wpgo-themes:/data/themes \
  wpgo:local

compose.yaml

docker/compose.yaml defines three services:

Service Purpose
db postgres:17-alpine, database wpgo, user and password wpgo, health-checked with pg_isready
wpgo the site, built from the Dockerfile, waits for the database to be healthy
test profile test: runs go test ./... in a Go container against the same database (make docker-test)

Environment of the wpgo service:

DATABASE_URL: postgres://wpgo:wpgo@db:5432/wpgo?sslmode=disable
WPGO_SITE_URL: ${WPGO_SITE_URL:-http://localhost:8088}
WPGO_UPLOADS_DIR: /data/uploads
WPGO_TRUST_DEV_KEY: ${WPGO_TRUST_DEV_KEY:-1}   # demo only

Add anything from the configuration reference there, for example the SMTP settings or WPGO_PLUGIN_KEYS.

Production changes

compose.yaml is the development setup (demo database password, PostgreSQL published on the host, the demo plugin signing key trusted). For production add the override compose.prod.yaml, which fixes all of that and refuses to start until the secrets are set:

WPGO_DB_PASSWORD=<strong password> WPGO_SITE_URL=https://example.com \
  docker compose -f docker/compose.yaml -f docker/compose.prod.yaml up -d --build

It takes the database password from WPGO_DB_PASSWORD (used for POSTGRES_PASSWORD and the DATABASE_URL), does not publish PostgreSQL, sets WPGO_TRUST_DEV_KEY=0 and passes WPGO_PLUGIN_KEYS through. POSTGRES_PASSWORD only applies when the pgdata volume is first created; on an existing database change the password first (ALTER USER wpgo PASSWORD '...').

Also:

  • Put a TLS-terminating proxy in front and set WPGO_SITE_URL to the https:// address (reverse proxy and TLS).
  • Set WPGO_SECRET explicitly if you run more than one wpgo replica.

Logs and restarts

docker compose -f docker/compose.yaml logs -f wpgo
docker compose -f docker/compose.yaml restart wpgo

Containers do not always come back after the Docker daemon restarts; docker compose up -d starts them again with their data intact. Add restart: unless-stopped to both services if you want that automatically.
